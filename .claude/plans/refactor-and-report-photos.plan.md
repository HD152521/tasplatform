## 3. 프론트 점검

`rules/web/design-quality.md` 기준으로 본다. 특히 이 프로젝트에서 실제로 아팠던 것들:

1. **겹침·가로 스크롤** — `boxSizing` 빠져 칸이 서로를 덮은 적이 있다. 1440·760 두 폭에서
   주요 화면을 전부 렌더해 재는 것을 **점검 항목으로 고정**한다.
2. **상태 표시의 일관성** — `지금 수집`, `파일 붙이기`, 첨부 받기가 각자 다른 말투로
   진행·성공·실패를 말한다. 문구 톤을 맞춘다.
3. **대기 중 침묵 금지** — 수십 초 걸리는 동작(첨부, 수집)에서 화면이 조용하면 사람은
   다시 누른다. 이미 몇 곳은 고쳤고, 나머지를 훑는다.
4. **비활성 상태** — 버튼만 잠그고 입력은 안 잠가 중복 업로드가 났던 적이 있다.
   같은 실수가 다른 곳에도 있는지 본다.

바꾸는 것은 **눈에 보이는 결함만**. 취향 문제로 손대지 않는다.

## 5. 기능 수정 두 가지

### 5-1. 보고서 4단계 — 사진 입력 (건너뛰기 가능)

**실측으로 확인한 것.** 실제 고객 보고서(`NH은행_프라이빗 클라우드_월정기보고서`, 17장)의
**15·16번 슬라이드**가 사진 슬라이드다.

```
슬라이드 15   "04" / "PaaS (1/2)"   그림 1장  8.07 × 5.43 in  (left 1.43, top 1.55)
슬라이드 16   "04" / "PaaS (2/2)"   그림 1장  7.88 × 5.43 in  (left 1.53, top 1.55)
```

**"2장씩" 은 한 슬라이드에 두 장이 아니라, 사진 슬라이드가 두 장**이고 각각 한 장씩
전면으로 들어간다.

> ⚠ 우리 템플릿(`templates/monthly-report.pptx`)은 **12장**이고 사진 슬라이드가 없다.
> 17장짜리는 다른 양식이다. **어느 쪽에 넣을지 확인이 필요하다** — 우리가 만드는
> 12장 보고서 끝에 붙이는 것이 맞는지, 아니면 템플릿부터 바꿔야 하는지.

**단계 배치.** 지금 4단계가 "보고서 생성" 이다. 요청대로 사진을 4번째에 넣으면
**보고서 생성이 5단계**가 된다.

```
1 인스턴스 수 → 2 SR 선택 → 3 작업 내역 → 4 사진(건너뛰기 가능) → 5 보고서 생성
```

`app/report/Stepper.tsx` 의 `STEPS` 에 한 칸을 더하고, `readStep` 의 상한과
`app/report/page.tsx` 의 분기를 함께 고친다.

**건너뛰기 표시.** 요청대로 체크 표시로 구분한다. 지금 Stepper 는 **지나간 단계를 전부
`✓`** 로 칠한다. 그러면 "건너뛴 것" 과 "한 것" 이 같아 보인다. 그래서:

| 상태 | 표시 |
|---|---|
| 사진을 넣었다 | `✓` (초록) |
| 건너뛰기를 눌렀다 | `—` (회색) + "건너뜀" |
| 아직 안 정했다 | 숫자 |

건너뛰기는 **명시적으로 눌러야** 한다. 그냥 지나친 것과 구분해야, 보고서 만들 때
"사진 없이 만들까요?" 를 물어볼지 말지가 정해진다.

**저장.** 사진은 크다. 결정할 것:

- **어디에** — `report_photos` 테이블(base64)인지, 디스크인지. TAS 는 파일시스템이
  ephemeral 이라 디스크는 재시작에 날아간다 → **DB 가 맞다.**
- **얼마나** — 보고서를 만들고 나면 필요 없다. 그 달 보고서가 나온 뒤 지우거나,
  첨부처럼 기간을 둔다. 권장: **그 달 것만 유지, 새로 올리면 교체.**
- **상한** — 슬라이드 한 장에 8×5.4인치다. 원본 그대로 받을 이유가 없다.
  **장당 4MB 상한 + 긴 변 1600px 로 줄여 저장**을 권한다.

**파이썬 쪽.** `scripts/build_report.py` 가 사진을 받아 슬라이드에 넣어야 한다.
지금은 텍스트만 갈아끼운다. 사진은 `add_picture` 로 넣되 **위 실측 좌표·크기**를 쓴다.

### 5-1 확정 — 사진 4장, 슬라이드당 2장

6월 보고서(167장)를 재 보니 두 배치가 있다.

    04 / PaaS (1/2), (2/2)      사진 1장   8.5 × 5.43 in            전면
    3-4 SDN, 05 CUNi 등          사진 2장   3.9 × 5.5 in   좌 1.45 / 우 5.42

**4장을 받으므로 나란히 배치(슬라이드당 2장 × 2슬라이드)** 를 쓴다. 그 양식에서
사진 페이지만 가져와 위치를 고정하고, 받은 순서대로 좌→우, 앞 슬라이드→뒤 슬라이드로 넣는다.

    1번 → 슬라이드 A 왼쪽      2번 → 슬라이드 A 오른쪽
    3번 → 슬라이드 B 왼쪽      4번 → 슬라이드 B 오른쪽

좌표(인치): 왼쪽 left 1.45 / 오른쪽 left 5.42, 공통 top 1.5, 폭 3.9, 높이 5.5.

덜 넣으면 넣은 만큼만 만든다. 0장이면 슬라이드를 아예 붙이지 않는다 —
빈 사진틀이 남은 보고서를 고객에게 보내는 것이 가장 나쁘다.


### 5-2. 인스턴스 수 — 합친 뒤에 반올림

**지금:** 아홉 칸을 먼저 반올림하고 더한다.

```ts
const input = { bank: roundEnv(rawInput.bank), ... };   // ← 여기서 먼저 반올림
const bankProd = input.bank.prod + input.bank.dr - (input.shared.prod + input.shared.dr);
```

**바뀔 것:** 소수 그대로 더하고, **Container 열에 넣기 직전에** 반올림한다.

```
지금    round(133.4) + round(133.4) = 133 + 133 = 266
바뀜    round(133.4  +  133.4)      = round(266.8) = 267
```

**이 변경이 건드리는 자리 — 그냥 옮기면 깨진다:**

1. **공동 배분** `splitShared` 가 `ceil/floor` 로 은행·중앙회를 나눈다. 소수를 넣으면
   `ceil(133.4/2)=67`, `floor=66` 처럼 합이 안 맞는다. **배분 전에 공동값을 반올림**해야
   한다.
2. **행 합계 vs 총합.** 행마다 따로 반올림하면 여섯 행의 합과 총합 반올림이 어긋난다
   (앞선 작업에서 실제로 겪어 입구 반올림을 택한 이유다). 총합을 어떻게 낼지
   **정해야 한다** — 행 합계를 더할지, 원값 총합을 반올림할지. 둘은 1 차이가 난다.
3. **전월 대비 증감.** 전월값도 같은 규칙으로 처리해야 증감만 소수로 남지 않는다.
4. **기존 테스트.** 10월 기대값이 입구 반올림 기준(`[667,188,360,68,221,123]`, 합 1627)
   으로 잠겨 있다. **새 규칙의 기대값을 엑셀 원본으로 다시 계산**해 바꾼다.

작업 전에 `정기점검인스턴스계산.xlsx` 의 수식을 다시 열어 **엑셀이 어느 시점에
반올림하는지** 확인한다. 그게 정답이고, 우리는 거기 맞추는 것이다.

### 5-3. SR 대화마다 번역 버튼 (신규 요청)

지금은 케이스 화면 위쪽에서 **한 번에 전체를 번역**한다. 원문이 한국어인 글까지
같이 번역되고, 몇 개만 보고 싶을 때도 전부 기다려야 한다.

글 하나하나에 번역 버튼을 두어 **원하는 것만** 번역한다.

이미 있는 것을 그대로 쓴다:

- `text_translations(scope, ref_id, lang)` — 스레드 한 건 단위로 이미 저장된다.
  한 번 번역한 글은 다시 부르지 않는다.
- `app/TranslateButton.tsx` — 보안 공지·기술 문서에서 쓰는 per-item 번역 버튼.
  같은 모양을 케이스 대화에 붙인다.

정할 것:

- **위쪽의 전체 번역을 남길 것인가.** 남기면 두 가지 방식이 공존한다. 대화가 수십 개인
  케이스에서는 전체가 편하니 **남기되**, 개별 버튼과 상태가 어긋나지 않게 한다
  (이미 번역된 글은 버튼이 "원문 보기" 로 바뀌어야 한다).
- **원문이 한국어인 글**은 번역 버튼을 흐리게 두거나 숨긴다. `lib/caseTranslate.ts` 의
  `needsTranslation` 이 이미 그 판정을 한다.

케이스 본문·답변은 AI 로 나가므로 **반드시 `lib/aiChat.ts` 경유**여야 한다
(사내 LLM 우선, 없으면 OPENAI_API_KEY). `lib/translate.ts`(Gemini/Groq)로는 보내지 않는다.

## 6. 순서

```
1  5-2 인스턴스 반올림    ← 작고, 엑셀이 정답을 갖고 있다. 먼저 맞춘다
2  reviewer 2종 (격리)     ← 리팩터링 전에 돌려야 무엇을 고칠지 목록이 나온다

4  3 프론트 점검
5  5-1 사진 단계           ← 가장 크다. 저장·상한·템플릿 확인이 선행
```

**5-1 은 확인 두 개가 먼저다** — 12장 보고서에 붙일지 17장 양식으로 갈지,
그리고 사진 저장 방식(DB·상한·보관). 그 답이 없으면 만들어도 다시 만들게 된다.
